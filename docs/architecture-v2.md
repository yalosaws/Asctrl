# Asctrl v2：从「遥控一台电脑」到「让 AI 给电脑编程」

> 状态：架构提案（2026-11-17），基于 v0.2.0 代码通读。P1 已完成，P2 完成了第一部分（见第 5 节），其余未实施。

## 一句话

现在的 Asctrl 是**一个更聪明的远程鼠标键盘**：AI 仍是控制回路本身，驱动按它写好的直线脚本去模拟人。
v2 要把它反过来：**驱动是一个常驻、事件驱动、可编程的运行时，它持有电脑的实时世界模型；AI 只写程序和处理升级**，绝大多数时间不在回路里。

---

## 1. 现在做对了什么（要保留）

- **按文字指向**（`target: "Save"`）而不是坐标：这是对的抽象，v2 继续以语义目标为一等公民。
- **回复携带差异**（report.rs）：不让 AI 再看一次。v2 把它推到极致——AI 订阅变化，而不是在每次动作后收到变化。
- **防陈旧点击**（Frame 校验）、**屏幕稳定判定**（screen.rs 的噪声瓦片记忆）：工程质量很高，直接复用。
- **计划在驱动侧批量执行**（batch.rs）：方向正确，只是走得不够远。

## 2. 根本瓶颈（不是 bug，是架构选择造成的天花板）

| # | 瓶颈 | 代码里的证据 | 后果 |
|---|---|---|---|
| B1 | **前沿模型仍是控制回路**。计划是不带分支的直线步骤；任何偏离都回到 AI | `run.ts` 的 `Plan` 只有 steps / repeat / on；失败即 `fail()` 并取消后续计划 | 每次意外 = 一次数秒到数十秒、数千 token 的往返；任务成功率受「盲写计划」准确度上限约束 |
| B2 | **感知是拉取式快照**，没有持续的世界状态 | 全仓库没有 UIA 事件处理器（仅 overlay 用了 `SetWinEventHook` 监听前台）；变化靠 30 ms 轮询像素差（`screen.rs` `POLL`） | 不知道「刚才发生了什么」，只知道「现在和上次读的差多少」；每次动作后都要重新读树、截图、等稳定 |
| B3 | **唯一的执行通道是模拟人**：一个鼠标、一个焦点、一把全局锁 | `tools/mod.rs` `static ACTING: Mutex`；`input.rs` 全部是 `SendInput`；无 CDP、无 COM 自动化、无后台消息 | 不能并行做两件事；用户和 AI 抢同一套键鼠；浏览器 / Electron / Office 只能从像素和贫瘠的 UIA 树里猜 |
| B4 | **不积累知识**。除了 Drex 的「措辞→控件」别名缓存，每个任务从零开始 | `run.ts` `Drex.remember`，键是 `program|title|kind|text` | 第 100 次发邮件和第 1 次一样贵 |
| B5 | **层间协议是给人读的散文**，再用正则解析回来 | `run.ts` `parseControls` 用正则从 observe 文本里抠 `[e12] Button "Save"`；`effectOf` 用正则判断「屏幕变没变」 | 改一句回复措辞就可能破坏控制台；结构化信息在边界上丢失 |
| B6 | **恢复逻辑在控制台而不在驱动**。`recover()` 里每一轮都要 `observe`、`click`、再调工具 | `run.ts` `recover` / `scope` / `fail` 都是 `this.call(...)` | 走中继（远程、HTTP 连接器）时，每次恢复是多次公网往返；本地快的东西远程就慢 |

外加两个技术性限制，同属感知层：GDI 截图（被遮挡窗口抓不到、硬件加速内容可能黑屏）；没有 Set-of-Marks 或视觉定位，自绘 UI 只能靠 OCR。

**结论**：继续在 v0.2 上加功能（更多步骤类型、更聪明的 Drex 提示）是在 B1–B3 的天花板下做局部最优。颠覆点在于换掉三件事：**谁在回路里、状态从哪来、手从哪伸进去**。

## 3. v2 架构

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 前沿模型（Claude 等）  —— 秒级：理解目标、写程序、处理升级                    │
└───────────────▲───────────────────────────────┬──────────────────────────────┘
                │ 升级（结构化状态 + 问题）      │ 程序 / 查询（MCP，≈5 个工具）
┌───────────────┴───────────────────────────────▼──────────────────────────────┐
│ 驱动运行时 Asctrl Runtime（Rust，跑在被控电脑上）                              │
│                                                                              │
│  L3 认知分级     反射(μs–ms) → 本地小模型(10–300ms：定位/消歧/判断) → 升级      │
│  L2 程序执行器   沙箱脚本：await / if / 循环 / 事件处理器 / 断言 / 效果声明      │
│  L4 技能库       成功程序 → 参数化技能，按「应用 + 屏幕指纹」检索                  │
│  L1 执行通道     语义 API > UIA 模式 > 窗口消息 > SendInput（最后手段）          │
│  L0 世界模型     事件驱动的全局状态图 + 时间线（UIA 事件、WinEvent、WGC 帧、       │
│                  CDP DOM、增量 OCR），每个元素有身份、来源、置信度                │
│  L5 安全与事务   效果分级、检查点、不可逆动作在本机确认、动作日志                  │
└──────────────────────────────────────────────────────────────────────────────┘
```

### L0 世界模型：从「快照」到「活的状态图」

驱动常驻维护一张**全局状态图**，而不是被调用时才去读：

- **来源融合**：UIA（订阅 StructureChanged / PropertyChanged / Focus / WindowOpened 事件，而不是每次 `FindAll`）、WinEvent 钩子、**Windows Graphics Capture** 帧流（带脏矩形，可抓被遮挡窗口，替代 GDI）、Chromium/Electron 的 **CDP**（DOM 和无障碍树，网页不再是像素）、只在脏区上跑的增量 OCR、按需的视觉模型（自绘 UI）。
- **统一节点**：每个元素一个稳定身份（沿用现有 Registry 的引用思想，扩展到跨来源），带 `source`（uia / dom / ocr / vision）和 `confidence`。同一个按钮从 UIA 和 DOM 都看得到时合并为一个节点。
- **时间线**：每个变化是一条带时间戳的事件。「刚才弹出了什么」「这个数字过去 5 秒怎么变的」都是查询，不是重新观察。现在的 `watch`、`wait_for`、弹窗检测、屏幕稳定判定，全部变成对时间线的订阅。
- **屏幕指纹**：对当前窗口的结构（而非内容）做哈希，用来识别「我在 Gmail 的写信界面」。这是 L4 技能检索的钥匙。

收益：动作后的「等稳定 + 读树 + 求差」变成「等待一个事件」；感知成本与变化量成正比，而不是与屏幕大小成正比。

### L1 执行通道：输入设备是最后手段

每个动作由驱动选择**最高层、最不打扰**的通道：

1. **语义 API**：PowerShell / 文件系统 / URL 协议 / Office COM / CDP `Runtime.evaluate` 和 `Input.dispatch*`。能用 API 填表就不点。
2. **UIA 模式**（现有 `press` / `set_value` 已部分做到）：不需要焦点，不动鼠标。
3. **窗口消息**（`PostMessage` WM_CHAR / BM_CLICK 等）：后台窗口可用。
4. **SendInput**：需要前台和独占，仅用于游戏、远程桌面、拒绝其他通道的程序。

当只有第 4 档需要独占时，**全局 `ACTING` 锁就可以降为按窗口加锁**：两个程序可以在不同窗口里并行执行，用户也可以继续用自己的鼠标。

更进一步，可选的 **Agent 桌面**：在独立的 Windows 桌面对象 / 第二个用户会话（RDP 回环）/ Windows Sandbox 里给 AI 一个自己的工作区，用户的屏幕完全不受干扰。overlay 变成「透过窗户看 AI 干活」，而不是「AI 接管我的电脑」。

### L2 程序而非计划：AI 写代码，驱动跑代码

把 JSON 步骤列表换成一个**在驱动里沙箱执行的小脚本**（嵌入式 JS 引擎如 QuickJS / Boa，或 Rhai），API 直接面向世界模型：

```ts
// 前沿模型写的程序：一次下发，在被控电脑本地运行
const mail = await app.open("https://mail.google.com", { ready: ui.text("Compose") });
on(ui.dialog({ has: "Leave site?" }), d => d.press("Leave"));        // 真正的事件处理器

for (const row of args.recipients) {
  await mail.press("Compose");
  await ui.fill({ To: row.email, Subject: args.subject, "Message Body": row.body });
  await act.irreversible(() => ui.press("Send"));                     // 效果声明，见 L5
  await expect(ui.text("Message sent"), { within: 10_000 });
}
return { sent: args.recipients.length };
```

它统一并替代了现在的 `run` / `repeat` / `on` / `watch` / `grids` / `check` / `when`：循环、分支、等待、反应都是语言本身的能力。止盈止损不再是专门的 `watch` 步骤，而是

```ts
const price = ui.number(region);           // 时间线上的一个可订阅值
await until(() => price.value >= 141 || price.value <= 133);
await ui.press("Sell all");
```

脚本内部不暴露原始坐标和 SendInput，只能通过 L1 的通道表；脚本的文件 / 网络 / Shell 能力由会话的授权范围决定。

### L3 认知分级与升级协议

| 层 | 延迟 | 谁 | 做什么 |
|---|---|---|---|
| 反射 | μs–ms | 运行时本身 | 精确匹配、等待、事件处理器、弹窗规则、数值触发 |
| 小模型 | 10–300 ms | 本地或近端模型（Drex 的位置，加本地视觉定位模型） | 措辞消歧、「这个对话框是不是障碍」、自绘 UI 定位、`check` 类判断 |
| 升级 | 秒级 | 前沿模型 | 程序抛出无法处理的情况时才介入 |

**升级不是失败**。程序遇到未知时，运行时**挂起**（不是终止）程序，把结构化的升级包发给 AI：程序位置、局部变量、时间线最近 N 个事件、相关子图、可选截图。AI 的回答可以是一段补丁代码，运行时从挂起点继续。现在「失败 → 取消所有排队计划 → AI 重新规划全部」的模式消失。

### L4 技能库：越用越快

- 程序成功跑完（含断言），运行时把它**参数化并存为技能**，键是「应用 + 版本 + 屏幕指纹 + 意图描述」。
- 下次 AI 说「发邮件给 X」，先在技能库里检索；命中则零规划直接执行，小模型只负责填参数。
- 技能执行中屏幕指纹对不上（应用改版），降级为普通程序 + 升级，修复后的版本覆盖旧技能。
- 现在的 `drex-cache.json`（「只在整个计划成功后才记住」）就是这个想法的雏形，v2 把记忆的粒度从「一个措辞」提升到「一段流程」。
- 技能可导出、共享、审计：它是可读的代码，不是不透明的权重。

### L5 效果分级、事务与安全

- 每个动作带**效果等级**：`read` / `reversible` / `irreversible` / `external`（对外发送、付款）。运行时按等级套用策略，而不是靠 `DESTRUCTIVE` 正则猜。
- `irreversible` 和 `external` 默认在**被控电脑本机确认**（overlay 弹出），远程 AI 无法绕过。这同时补上 README 里「危险命令本机确认」的待办。
- 世界模型提供前置 / 后置条件的校验，所以「发出去了吗」由时间线回答，而不是由 AI 再截一次图。
- 所有动作、所选通道、升级、确认写入**本地只追加日志**（补上「动作日志」待办），技能库的每次自动执行同样可追溯。

### 对外接口：30 个工具收缩到 5 个

| 工具 | 作用 |
|---|---|
| `connect` | 不变 |
| `query` | 查询世界模型：子图、元素、时间线片段、截图（含 Set-of-Marks 标注） |
| `exec` | 下发程序（或调用技能），立即返回句柄；事件和结果以流 / 通知回传 |
| `act` | 单个动作，用于手动修正（保留现有 `click` / `type` / `set_value` 的语义，合并为一个） |
| `resume` | 回答一次升级：补丁代码或决定 |

Shell、文件、剪贴板、窗口管理在 v2 里是**程序内的库函数**，不再是独立工具。工具少了，前沿模型的提示负担和选错工具的概率都下降。

驱动与控制台之间改为**带 schema 的结构化协议**（节点、事件、升级包都是类型化 JSON）；面向人类的散文只在 MCP 边缘渲染一次。

## 4. 现有代码去留

| 模块 | 去向 |
|---|---|
| `uia.rs`（Registry、稳定引用、读树） | **保留并改造**：从按需 `FindAll` 改为事件订阅维护的增量树 |
| `screen.rs`（稳定判定、噪声瓦片） | **保留**，输入源从 GDI 轮询换成 WGC 帧 + 脏矩形 |
| `capture.rs`（GDI） | **替换**为 Windows Graphics Capture |
| `ocr.rs`、`grid.rs` | **保留**，改为只处理脏区，结果进世界模型 |
| `locate.rs`（按文字评分） | **保留为反射层**的匹配器，候选来源扩展到 DOM 和视觉 |
| `input.rs` | **保留为第 4 档通道**；新增 UIA / 消息 / CDP / COM 通道和通道选择器 |
| `tools/batch.rs` + `src/console/run.ts` | **由 L2 运行时取代**；`run.ts` 的 Drex 消歧逻辑下沉到驱动的小模型层 |
| `tools/report.rs` | 变成时间线到文本的渲染器，只在 MCP 边缘使用 |
| `link.rs`、中继、HTTP 连接器、overlay | **基本不变**；协议加版本号，消息改为结构化 |

## 5. 迁移路线（每阶段都可独立发布、可量化）

| 阶段 | 内容 | 验收指标 |
|---|---|---|
| **P0 基准** | 先建真实任务集：浏览器、设置、Office、Electron（VS Code / 微信）各 10 个任务，记录成功率、总时长、前沿模型调用次数和 token | 现有 v0.2 的基线数字（README 承认目前没有） |
| **P1 结构化协议 + 恢复下沉** | 驱动回复带类型化 `data`；`recover()` 移到驱动 | `parseControls` 等正则删除；远程场景恢复耗时下降 |
| **P2 活的世界模型** | UIA 事件订阅、WGC、时间线；`watch` / `wait_for` / 弹窗检测改为订阅 | 动作后平均等待下降；被遮挡窗口可截图 |
| **P3 CDP 通道** | Chromium / Edge / Electron 走 DOM | 浏览器任务成功率显著提升，像素定位占比下降 |
| **P4 程序运行时 + 升级协议** | 嵌入脚本引擎，`exec` / `resume`；旧 `run` 编译成脚本保持兼容 | 每个任务的前沿模型调用次数（核心指标） |
| **P5 技能库** | 成功程序参数化存储与检索 | 重复任务的第 2 次及以后：零规划调用的比例 |
| **P6 后台通道与 Agent 桌面** | 按窗口加锁、PostMessage、独立桌面 / 会话 | 用户和 AI 同时操作不冲突；两个任务并行 |

P1 是低风险高收益的起点，即使后面方向调整也不会白做。

### P1 完成情况（2026-11-17）

- 驱动回复带类型化 `data`（`src/shared/protocol.ts`：`ActionData`、`BatchData`、`ObserveData`）：动作的 `effect`，未命中的 `miss`（`ambiguous` / `absent` / `stale` / `other`）及候选控件，observe 的 `windows`，批处理失败时的 `where`。
- `run.ts` 里的 `parseControls`、按措辞判断屏幕变化和未命中、从 observe 文本解析窗口列表的正则全部删除；候选控件的筛选（`shortlist`）移到驱动的 `tools/recover.rs`。
- 本地恢复下沉到驱动：`on` 规则、快速输入后的短暂等待、候选列表都在批处理内部完成；恢复成功的步骤不再中断批处理，失败时附带现场，控制台不必再 observe。
- 决策模型（Drex）仍在控制台调用：API 密钥不该放到被控电脑上，这一步留给 P4 的认知分级。
- 结果：单元测试 36/36、计划测试 17/17，端到端测试和 HTTP 连接器测试全部通过。同一个新驱动下用旧版和新版 run.ts 对比，需要决策模型的计划驱动调用减少约 20%（10→8，11→9），不需要恢复的计划不变（4 次）。本地连接下耗时基本不变；收益在中继和远程场景，每少一次调用就少一次公网往返。
- 第二轮（同日）：
  - 计划的开始和结束标记随第一个和最后一个批处理一起发（`batch` 的 `mark` / `end` 参数，结束时弹窗处理记录放在 `ended`），只有计划以 `when` 或 `check` 开头、或中途失败后才单独调用 `plan_mark`。
  - 记忆作用域（哪个程序、哪个窗口）只在确实记有这个措辞的别名时才去查；恢复时直接用驱动在 `miss.window` 里给出的窗口。
  - `request_admin` 用 `data.restarting` 判断提权重启，控制台里已经没有按回复措辞做的判断。
- 第二轮结果（同一组计划测试，驱动调用次数，P1 之前 → 第一轮 → 第二轮）：不需要恢复的计划 4 → 4 → 1；需要决策模型的计划 10 → 8 → 5，11 → 9 → 5；用到记忆的计划 4 → 4 → 2。计划测试 17/17、单元测试 36/36、端到端 59/59、HTTP 连接器测试全部通过。
- 未覆盖：`request_admin` 的新判断需要 UAC 确认，自动测试跑不到；计划开始标记现在在批处理内部发出，overlay 上的显示顺序只能人工看。

### P2 第一部分完成情况（2026-11-17）

- **窗口时间线**（`events.rs`）：WinEvent 钩子（进程外）记录顶层窗口的显示、隐藏、销毁、到前台、最小化、还原、改标题，每条带序号、时间、标题（事件发生时就记下，窗口关掉后仍能叫出名字）和进程。等待方按序号订阅，而不是固定间隔轮询；`ASCTRL_NO_EVENTS=1` 关掉后一切回到原来的轮询。
- 接入方：`wait_for` 的每轮等待改为"有窗口事件就提前醒，最多 100 ms"；弹窗监视器在 60 ms 轮询和"有窗口出现就醒（给 40 ms 让它画完按钮），否则每 250 ms 看一次"之间二选一；批处理返回运行期间出现、消失、到前台的有标题窗口（`BatchData.windows`）。
- **被遮挡窗口的读取**（`wgc.rs`）：Windows Graphics Capture 截取单个窗口自己画的内容。只有在要读的区域被其他程序的窗口盖住时才用，文字目标、`observe` 和 `wait_for` 的文字识别都走它；没盖住时仍用原来的屏幕截图。
- 顺带修了一个以前就有的问题：文字识别找到的目标原来记在"当时最上层的窗口"名下，点击前也不会把目标窗口挪到前面，所以被盖住时会点到盖在上面的程序。现在命中点归属正在读的窗口，点击前先把它带到前面。
- 实测（计算器最大化盖住测试窗口）：画布上的 `CANVAS-7391` 在 104–145 ms 内读出，点击后计数加一。批处理报告出对话框在 877 ms 到前台、884 ms 显示、1341 ms 隐藏、1346 ms 销毁。
- **没有达到的**：时间线没有让 `wait_for` 变快：开、关时间线都约 1030–1046 ms 发现 800 ms 后弹出的对话框。瓶颈不在轮询间隔，而在找到窗口后等它画稳（`wait_stable`）以及点击本身的稳定等待。"动作后平均等待下降"这个验收指标还没做到，要靠下一部分：用界面事件判断"已经稳定"，代替连续两帧像素相同。
- 测试：单元测试 39/39、计划测试 17/17、端到端 59/59、HTTP 连接器测试、新增的 `test/p2.ts`（4 项）全部通过。
- 留到 P2 第二部分：UIA 事件订阅（控件结构和属性变化，按窗口限流）、截图本身改用 WGC、用事件缩短动作后的稳定等待。

### P2 第二部分进展（2026-11-17，未提交）

- **先量了时间花在哪**（新增 `test/settle.ts`，在测试窗口上每种动作轮流做 5 轮取中位数）：

- **用事件缩短安静期，结论是现在不做**：
  - 按钮在鼠标按下的一瞬间就会发出焦点和状态变化事件，比它打开的对话框早得多。
  - 所以"收到界面事件"不能当成"动作的效果已经出来了"。拿它提前结束等待，会漏掉 100–300 ms 后才出现的对话框。
  - 这条路要等能区分"按下本身的反馈"和"程序做出的反应"之后再走，例如订阅目标窗口的结构变化事件，排除被点控件自身的状态变化。

## 6. 风险与不做什么

- **脚本沙箱是新的攻击面**：必须是无宿主能力的引擎，所有能力经通道表授权；远程会话默认无 Shell / 文件写入，需本机授权提升。
- **事件订阅的性能和稳定性**：部分程序的 UIA 事件风暴会拖慢它们自己；需要按窗口限流，并保留按需读取作为后备。
- **技能被应用改版悄悄弄坏**：靠屏幕指纹 + 后置断言兜底，指纹不符就不自动执行。
- **CDP 需要浏览器以调试端口启动或安装扩展**：会改变用户的浏览器配置，必须显式同意；做不到时退回 UIA / 像素。
- **不做**：不训练自己的大模型；不追求跨平台（Windows 原生深度是优势）；不在 v2 第一版里做多 AI 协作。
