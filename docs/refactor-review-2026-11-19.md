# Asctrl 重构前审查

审查基线为 `computer-use-v2` 分支的 `3009c27`。这次按模块覆盖了仓库的全部一方运行时代码，并在 Windows 上构建和运行了真实驱动。最先要修的是操作目标的身份、日志中的用户内容、默认中继传输以及控制器交接。两个同标题网页已经能让驱动读错页，显式指定不存在的窗口也能让等待误报成功。下面区分了本机观察和源码判断，以便选取回归用例。

## 主调用路径

stdio 和 HTTP 入口都通过 `createAsctrlServer` 发布工具。一次普通调用经 `TechClient` 直达本机驱动或经过中继，再由 Rust 驱动分派给工具。计划另经过 TypeScript 的 `Runner`，可拆成多次驱动调用。HTTP 端按访问密钥和客户端复用 `Link`，所以关闭一次 MCP 会话、切换受控电脑、结束驱动会话是三个不同的事件。[MCP 入口](../src/console/mcp-server.ts#L140) · [HTTP 连接复用](../src/console/mcp-http.ts#L69) · [驱动分派](../agent-app/src-tauri/src/link.rs#L92)

## 审查发现

1. **P1 · 公网中继默认使用明文 WebSocket，日志保留完整配对码。** 发布版驱动的默认公网地址和仓库的 MCP 配置都使用 `ws://`。连接器的 HTTPS 只保护到连接器的那一段。采用仓库默认配置时，跨公网的配对和工具消息缺少传输加密。中继还会在设备上线、配对和离线时记录六位码。应先准备可验证证书的 WSS 端点，再切换发布默认值。本机回环可继续使用 WS。日志可用与配对码无关的连接标识关联事件。[驱动默认值](../agent-app/src-tauri/src/link.rs#L48) · [MCP 配置](../.mcp.json#L7) · [中继日志](../src/relay/server.ts#L113)

2. **P1 · 新控制器可以在旧控制器的清理过程中接入。** `detach` 先清空 `controller`，随后异步重置所有控制器共用的 `Ctx`。重置会等待后台工作，再取走当前 shell、清空截图和 UIA 引用。此时 `attach` 已经允许新控制器接入，旧清理可能清掉新会话刚建立的状态。另一个相关窗口在分派端，任务被调度后才读取全局会话编号。应在接收调用时绑定其所属会话，把结束、清理和再次接入的顺序写进会话生命周期。[控制器交接](../agent-app/src-tauri/src/lib.rs#L146) · [上下文清理](../agent-app/src-tauri/src/tools/mod.rs#L222) · [会话编号读取](../agent-app/src-tauri/src/tools/mod.rs#L308) · [调用分派](../agent-app/src-tauri/src/link.rs#L111)

3. **P1 · 认证数据的并发写入可能撤销一次密钥吊销。** 运行中的 HTTP 服务和 `keys` 命令都能修改同一个 JSON 文件。两边各自刷新、修改内存快照，再整文件替换。临时文件按进程隔离，但读取到提交之间没有跨进程锁。如果发放令牌与吊销密钥重叠，较早读到的快照可以覆盖较晚的吊销结果。应使完整的读改写操作串行化，或迁入支持事务的存储。[存储读写](../src/console/auth.ts#L75) · [吊销密钥](../src/console/auth.ts#L120) · [发放令牌](../src/console/auth.ts#L154)

4. **P1 · 并发编辑同一文件可能丢失已报告成功的修改。** 驱动可以并发分派文件调用。`edit` 先读取整份文件，在内存中替换文字，最后写回。两个请求即使改的是不同段落，也可能基于同一份旧内容。写入时同一进程和目标还会共用一个临时文件，替换失败后则直接写入目标。建议将同一文件的读取、校验和提交纳入同一写入边界，按次独占创建临时文件，原子替换失败时保留原文件并报告原因。[文件工具入口](../agent-app/src-tauri/src/tools/system.rs#L70) · [临时文件与替换](../agent-app/src-tauri/src/files.rs#L154) · [精确编辑](../agent-app/src-tauri/src/files.rs#L225)

5. **P2 · 紧凑模式把有写入效果的技能操作声明为只读。** 完整工具面把 `skills` 标为可写。紧凑工具面按工具名将整个 `skills` 放进带 `readOnlyHint` 的 `query`。其中 `import` 可以替换技能，`forget` 可以删除技能。依赖 MCP 元数据的客户端会向用户展示错误的操作性质。应按子操作划分读写入口，并从同一份工具定义生成紧凑版和完整版的元数据。[技能参数](../src/console/mcp-server.ts#L649) · [紧凑版分组](../src/console/mcp-server.ts#L973) · [只读声明](../src/console/mcp-server.ts#L1001) · [驱动的写入分支](../agent-app/src-tauri/src/tools/skills.rs#L333)

6. **P2 · 轮询进度会取走尚未写完的失败报告。** `fail` 在等候现场信息前就将任务标为失败，`progress` 会把这种任务标为已报告并移出列表。本次用内存假驱动延迟返回现场信息，先查询得到耗时 `0.0 s` 的失败报告，释放等待后再次查询得到 `Nothing queued or running.`，现场信息丢失。应在耗时、现场摘要、后续任务的取消状态都写入后，一次性发布终态。[取走报告](../src/console/run.ts#L394) · [写入耗时](../src/console/run.ts#L532) · [提前标记失败](../src/console/run.ts#L547)

7. **P1 · 同标题标签页会读错，也可能点错。已实测读错页。** 在同一浏览器窗口打开两个标题相同、正文分别为 A 和 B 的本地页面。让页面通过可见性事件独立报告哪一页在前台。切回 A 后，指定这个窗口调用 `read_text`，返回的仍是 B，通道为 `page`。按窗口选择标签页的实现取标题前缀最长的一项，平分时没有核对活动标签页。按文字点击和填表也经过该选择器。应把窗口和活动标签页身份带到实际调用处，无法唯一识别时返回明确结果。[选页](../agent-app/src-tauri/src/cdp.rs#L495) · [扩展列举标签页](../browser-extension/background.js#L80) · [网页工具](../agent-app/src-tauri/src/tools/web.rs)

8. **P1 · 显式指定的窗口不存在时，等待仍能成功。已实测。** 测试窗口中显示 `Submit`，另一指定窗口从未创建。对后者调用 `wait_for` 等待 `Submit` 返回成功，等待 `stable` 也返回成功。计划因此可能在界面尚未出现时进入下一步。等待文字时每次轮询都会重新查找指定窗口，但找不到时静默改查前台窗口。`stable` 只在开始时解析一次窗口，解析失败同样退回前台窗口。应区分“调用方未指定窗口”和“指定窗口尚未找到”，后者不退回前台，并让 `stable` 也在每次轮询时重新查找目标。[窗口解析](../agent-app/src-tauri/src/tools/wait.rs#L130) · [稳定检测](../agent-app/src-tauri/src/tools/wait.rs#L140) · [文字检测](../agent-app/src-tauri/src/tools/wait.rs#L175)

9. **P1 · 操作日志会保留表单值和文件内容。已实测。** 通过正常的多字段填表写入合成标记，在日志的 `args.fields[0].value` 读到了原文。文件测试的日志也包含 `write_file.content` 和 `upload_file.data`。清理代码按对象处理 `fields`，实际接口接收数组。建议按工具列出可记录的字段，并对嵌套步骤、返回摘要使用同一规则。验收时向各入口传入合成标记，检查所有持久日志，同时保留结果和耗时供排障。[日志构造](../agent-app/src-tauri/src/safety.rs#L158) · [多字段实现](../agent-app/src-tauri/src/tools/values.rs#L108)

10. **P1 · 遮挡窗口的 OCR 在抓取失败时可能读到覆盖它的窗口。源码判断。** `read_in` 已检测到窗口被遮挡，若窗口自身画面抓取失败或交集太小，仍回退到同一桌面矩形的可见像素。定位或等待可能把前方窗口的文字归给指定窗口。遮挡窗口能正常抓取的路径通过了测试。本次未强制制造 WGC 失败。应让抓取结果携带像素来源，目标窗口画面不可用时向调用方明确返回原因。[OCR 回退](../agent-app/src-tauri/src/ocr.rs#L97) · [定位调用](../agent-app/src-tauri/src/tools/locate.rs)

11. **P2 · 长文本自动粘贴可能丢失用户剪贴板的富文本格式。源码判断。** 默认输入超过 200 个字符时会尝试粘贴。原剪贴板只要提供 Unicode 文本，就进入保存字符串的路径。若同时有 HTML 或 RTF，恢复时会清空剪贴板并只写回纯文本。应在无法完整恢复时改用键入，并在独立桌面验证粘贴前后的文本和格式集合。[输入选择与恢复](../agent-app/src-tauri/src/tools/keys.rs#L51) · [读取](../agent-app/src-tauri/src/winmgr.rs#L666) · [清空与写回](../agent-app/src-tauri/src/winmgr.rs#L735)

12. **P2 · 程序超过规定时限仍可报告成功。已实测。** 通过真实驱动提交只休眠 2.2 秒并返回常数的脚本，设置执行上限 1 秒、调用方等待 4 秒。实际用时 2.20 秒，状态为 `done`，返回值为 17。宿主的休眠循环和工具回复等待没有共同遵守程序截止时间。应向这些等待传播截止时间，并在发布成功结果前再检查一次。[宿主休眠](../agent-app/src-tauri/src/tools/program.rs#L253) · [发布结果](../agent-app/src-tauri/src/tools/program.rs#L600)

13. **P2 · 本地控制断开并转到离线时，屏幕仍显示控制边框。** 原生状态允许从 `connected` 直接进入 `offline`。前端在 `ready` 才收起边框，离线分支只改变光球和配对卡。用构建后的前端注入连接、离线事件，页面状态变为离线后边框节点仍在。把退出控制的收尾逻辑放在离开 `connected` 的共同路径，并覆盖连接动画尚未结束时的断开。[原生状态](../agent-app/src-tauri/src/lib.rs#L102) · [界面状态](../agent-app/src/main.ts#L156) · [边框](../agent-app/src/edge.ts)

14. **P2 · 桌面基准清理可能关闭用户刚打开的其他程序。源码判断。** P0 用运行前后的顶层窗口句柄差集决定要关闭哪些窗口，其中没有任务所有权条件。独立清理脚本也按通用的 `test/…ts` 命令行匹配 Node 进程。应只清理本次启动且能归属到本次测试的窗口、进程和临时目录。可用同期启动的无关测试窗口验证它能保留。[P0 清理](../test/p0/run.ts#L148) · [独立清理脚本](../test/cleanup.ps1#L10)

15. **P2 · 窗口被遮挡时，要求带控件编号的截图会静默丢掉编号。已实测。** 用计算器盖住测试窗，再请求 `screenshot(window, marks=true)`。窗口仍在后方，调用返回了它自己的图像，回复没有任何控件引用。WGC 成功的分支先于标注逻辑返回，像素也没有经过绘制编号的步骤。应让两种捕获来源共用标注流程，并核对图上的编号与返回列表。[截图入口](../agent-app/src-tauri/src/tools/look.rs#L89) · [标注入口](../agent-app/src-tauri/src/tools/look.rs#L113) · [MCP 参数承诺](../src/console/mcp-server.ts#L302)

16. **P2 · 两个并行程序的弹窗规则会互相覆盖。源码判断。** 驱动允许最多四个程序同时运行或等待。每次程序注册弹窗处理规则时，都替换进程里唯一的观察器，并通过代数使旧的观察循环退出。即使两份脚本各自指定了不同窗口，后一次注册也可能让前一个程序停止处理弹窗。应按程序或计划保存规则和日志，验证停止一个任务后另一任务的规则仍有效。[并发上限](../agent-app/src-tauri/src/tools/program.rs#L77) · [规则注册](../agent-app/src-tauri/src/tools/program.rs#L291) · [覆盖旧规则](../agent-app/src-tauri/src/tools/popups.rs#L83)

17. **P2 · 两个并发打开请求可能破坏刚启动的浏览器连接。源码判断。** 两个请求都能在浏览器尚未就绪时通过已有连接检查。后一个请求取得启动锁后没有再次检查，直接删除前一次启动写下的调试端口文件，然后尝试用同一配置目录再启动浏览器。应在获得锁后复查连接。验收时同时打开两个本地地址，确认两个页面均可读，随后仍能连接原浏览器。[复用检查与启动锁](../agent-app/src-tauri/src/cdp.rs#L419) · [端口文件与启动](../agent-app/src-tauri/src/cdp.rs#L430)

另外有两处接口差异值得在拆分时固定下来。`timeline` 可用于驱动的 `batch`，计划的 `STEP_TOOLS` 列表却没有它。扩展的“空闲后重新连接”测试只断言回复来自 `page` 通道，未核对是不是暂停前的页面，无法发现重连后读错页。前者需要明确对外承诺，后者可用每页独有的正文标记验收。[计划工具表](../src/console/run.ts#L83) · [批处理工具表](../agent-app/src-tauri/src/tools/batch.rs#L26) · [重连断言](../test/ext.ts#L143)

## 建议的改动顺序和验收条件

先单独修复 7–9 和 1，分别为错页、错窗、日志内容和中继传输建立回归。再修复会话和持久化并发（2–4），随后拆计划、工具注册及界面状态。每一项可单独合并和验收。特别要保留以下三个桌面场景。

| 场景 | 验收条件 |
| --- | --- |
| 两个同标题标签页，两个不同的表单 | 在两页之间来回切换。指定窗口读取时始终返回可见页。在合成表单上填入标记后，仅目标页改变。 |
| 前台窗口已显示同名文字，目标窗口延迟出现 | 目标出现前保持等待。目标一直缺席时按时结束并说明原因。遮挡目标并模拟 WGC 不可用时保留正确窗口归属。 |
| 短时限程序、控制器交接以及离线 | 宿主等待按脚本时限退出，过期结果不记入成功技能。快速重连后的首条命令成功，断开后收起控制边框。 |

| 独立改动 | 验收条件 |
| --- | --- |
| 修复计划报告的发布时间 | 用假驱动分别阻塞现场读取和计划收尾。期间轮询仍显示执行中。收尾后，调用方能取到一次完整报告和队列取消结果。 |
| 修复中继默认传输和日志 | 发布配置使用 WSS，测试中继仍可在回环运行。握手、重连、错误日志中均不出现配对码。切换默认配置前验证端点和现有客户端能完成配对。 |
| 明确驱动会话的所有权 | 用可暂停的清理过程覆盖断开后立刻重连的次序。第二个控制器保有自己的 shell 和观察结果，上一会话排队的调用在断开后失效。同一 HTTP 客户端关闭并新建 MCP 会话仍能继续原连接。 |
| 分别修复认证存储和文件编辑 | 用两个进程同时修改临时认证库，吊销结果和另一进程的独立修改都保留。对同一测试文件并发编辑不同段落，两处修改均保留或向发生冲突的一方返回明确错误。模拟替换失败后，原文件字节完整。 |
| 拆分 MCP 工具注册与发布 | 用内存传输核对紧凑版和完整版的工具名、参数及读写声明。只读技能查询可用，修改技能走写入入口。HTTP 入口继续排除读写服务端磁盘的上传和下载工具。 |

这些测试稳定后，再从 `run.ts` 拆出计划校验与展开、队列与报告，最后迁移依赖驱动或模型的执行逻辑。`uia.rs` 和前端 `fx.ts` 各自有原生测试或录像回放。改动触及对应行为时，可沿现有测试边界拆分。[计划实现](../src/console/run.ts#L108) · [UIA 测试](../agent-app/src-tauri/src/uia.rs#L1336) · [动画回放](../test/fxcheck.ts)
